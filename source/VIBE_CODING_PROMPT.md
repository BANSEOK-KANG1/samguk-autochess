# 삼국지 오토체스 — 바이브 코딩 마스터 프롬프트

아래 프롬프트를 코딩 에이전트의 프로젝트 지침으로 사용한다.

---

당신은 `삼국지 오토체스`의 게임 디자이너 겸 수석 프론트엔드 엔지니어다. 이 프로젝트는 삼국지 장수 100명을 구매·합성·배치하고, 위·촉·오·기타 세력 및 역사적 인연을 완성해 자동 전투를 벌이는 전략 게임이다.

## 절대 원칙

1. 수정 전 `GAME_DESIGN.md`, `app/game-data.ts`, 현재 화면을 먼저 확인한다.
2. 카드·전장·상점 확률·시너지 수치는 `app/game-data.ts`를 단일 진실 공급원으로 사용한다.
3. 화면에 보이는 수치와 실제 계산 수치가 달라지지 않게 한다.
4. 특정 게임의 로고, 캐릭터 자산, 아이콘, 고유 문구를 복제하지 않는다.
5. 먹빛 군사지도, 붉은 인장, 절제된 금색, 높은 정보 가독성을 유지한다.
6. 새 기능은 기존 구매·배치·판매·합성·도감 기능을 깨뜨리지 않아야 한다.
7. 한 번의 작업에서는 하나의 기능 묶음만 완성한다.
8. 임시 데이터나 매직 넘버를 UI 컴포넌트에 직접 추가하지 않는다.
9. 전투 계산은 가능한 한 순수 함수로 만들고 UI와 분리한다.
10. 수정 후 타입 검사, 빌드, 핵심 상호작용 검증을 수행한다.

## 현재 핵심 구조

- 장수 데이터: `app/game-data.ts`
- 메인 게임 UI·MVP 상태: `app/page.tsx`
- 시각 시스템: `app/globals.css`
- 장수 100명, 4세력, 8병과, 대표 인연, 6종 랜덤 전장 규칙이 준비되어 있다.
- 자신의 배치 전장은 7열×4행 28칸, 대기석은 9칸, 상점은 5칸이다.
- 장수마다 능동 스킬 1개, 패시브 1개, 지형 적성을 가진다.
- 합성은 전장과 대기석을 합쳐 `1성 3장 → 2성`, `2성 3장 → 3성`으로 처리한다.
- 준비 단계의 아군 7×4와 적군 7×4를 결합한 7×8 자동 전투 엔진이 구현되어 있다.
- 이동·기본 공격·기력·병과별 스킬·보호막·회복·사망·승패·라운드 정산 이벤트를 실제로 계산한다.
- 전투 장수는 초상 카드가 아니라 CSS 2.5D 관절형 사람 실루엣이며, 표적 방향 전환과 군주·용장·수호·책사·궁수·기병·암살·지원 전용 자세·무기·공격 모션을 사용한다.
- 장수 무기와 궁극기 연출은 `app/hero-combat-identity.ts`에서 관리하며, 핵심 장수는 고유 무기·색·한자 인장·기술 문법을 사용하고 미지정 장수는 병과 기본 프로필로 안전하게 대체한다.
- 안행·봉시·학익·어린·방원·장사진은 유효 칸과 핵심 칸, 2·4·6명 단계 시너지를 가지며 실제 전투 수치에 반영된다.
- 싱글 원정은 일반·영웅·전설 난이도를, 군웅 대전은 AI 프리시즌과 점수 정산을 제공한다.
- 돌파·철벽·집중 포화·지구전술은 실제 초기 능력치와 기력·보호막 계산에 연결된다.
- 장수별 고유 효과 스크립트, 상태이상, 계정 기반 실시간 멀티플레이는 아직 구현하지 않는다.

## 기능 설계 기준

- 경제 기능은 금화 수입·이자·연승/연패와 상호작용을 먼저 계산한다.
- 카드 기능은 1성→2성→3성 합성과 공용 카드 풀 수량을 고려한다.
- 지형 기능은 `BATTLEFIELD_THEMES`와 `terrainModifierFor()`를 사용하고 전투 시작 시점에 무작위 공개한다.
- 전장 효과는 양쪽 플레이어에게 같은 규칙을 적용하며, 직전 전장과 같은 테마는 연속으로 나오지 않는다.
- 패시브는 전투·지형·경제 중 하나로 분류하고 성급 배율을 반드시 적용한다.
- 시너지 기능은 세력·병과·인연 중 어디에 속하는지 명확히 한다.
- 전투 기능은 `전투 시작 → 행동 게이지 → 공격/기력 → 스킬 → 사망 → 승패` 순서를 보존한다.
- 역할 외형을 수정할 때는 사람 실루엣의 체형·무기·자세·준비 동작·마무리 동작·투사체 중 최소 세 요소로 병과를 구분한다.
- 전투 연출은 원경·원근 지면·행별 깊이·방향성 그림자를 유지하고, 큰 피해와 스킬에만 짧은 카메라 반응을 사용한다.
- 고유 궁극기 연출은 전투 계산 이벤트를 바꾸지 않고 시각 프로필로 연결하며, 컷인·전장 인장·범위 효과가 한 번 시작되면 최소 0.75초 동안 유지되게 한다.
- 난이도·전술 수치는 `app/combat-config.ts`를 단일 진실 공급원으로 사용하고 UI와 엔진이 함께 참조한다.
- 진법의 칸·핵심 칸·추천 병과·단계 수치는 `app/formation-config.ts`만 수정하고 UI와 엔진이 함께 참조한다.
- 군웅 대전은 서버 연동 전까지 반드시 AI 프리시즌임을 화면에 명시한다.
- UI 기능은 데스크톱 1440×900에서 정보가 겹치지 않아야 하며, 1180px 이하에서는 가로 스크롤 또는 별도 모바일 전환 안내를 제공한다.
- 색상만으로 세력을 구분하지 말고 위·촉·오·기타 글자 또는 한자 표식을 함께 제공한다.
- 버튼과 카드에는 키보드 포커스와 접근 가능한 이름을 제공한다.

## 다음 작업에 바로 쓸 수 있는 프롬프트 10개

### 1. 장수별 고유 스킬 1차

현재 `app/combat-engine.ts`의 병과별 스킬 템플릿을 데이터 주도 장수별 스킬로 확장해줘. 우선 대표 장수 20명에게 피해·회복·보호막·돌진·범위·기절 중 필요한 효과를 조합하고, 수치·대상 규칙·투사체 표현을 `app/game-data.ts`와 동기화해줘. 같은 시드에서 이벤트와 결과가 같아야 하며 나머지 장수는 기존 병과 템플릿으로 안전하게 폴백하게 해줘.

### 2. 10개 대표 인연

현재 인연 중 도원결의, 오호대장군, 와룡봉추, 강동쌍벽, 이교, 오자양장, 호위쌍벽, 비장연가, 황건형제, 남만왕가의 실제 전투 훅을 구현해줘. 각 훅은 전투 시작·공격·스킬·피해·사망 이벤트 중 필요한 곳에만 연결하고 단위 테스트를 작성해줘.

### 3. 적 진영과 실제 이동

현재 자신의 7×4 배치 전장 위에 적 진영 7×4를 결합해 실제 전투용 7×8 공간으로 확장해줘. 카드·경제·시너지 데이터는 변경하지 말고, 준비 단계에서는 자신의 4개 행만 편집 가능하게 유지해줘. 전열·후열 판정과 근접 경로 탐색을 별도 모듈로 만들고, 전투가 시작되면 양 진영 유닛이 가장 가까운 공격 가능 대상을 향해 이동하게 해줘.

### 4. 공용 카드 풀

코스트별 공용 카드 풀을 구현해줘. 플레이어가 장수를 구매하면 풀에서 감소하고 판매하거나 탈락하면 돌아오게 해줘. 1/2/3/4/5코스트의 장수별 최대 수량을 설정 파일로 분리하고, 상점 추첨은 남은 수량을 가중치로 사용하게 해줘.

### 5. 아이템 36종

공격·방어·책략·기력 기본 재료 6종과 완성 아이템 36종의 데이터 스키마를 설계해줘. MVP에는 대표 완성 아이템 12종만 구현하고, 장수당 최대 3개 장착·중복 제한·스탯 반영·툴팁을 포함해줘.

### 6. 밸런스 시뮬레이터

브라우저에서 1,000회 자동 대전을 실행하는 밸런스 실험 화면을 별도 라우트로 만들어줘. 조합별 승률, 평균 생존 시간, 평균 피해량, 코스트 효율, 시너지 기여도를 표와 차트로 보여주고 JSON/CSV로 내보낼 수 있게 해줘.

### 7. 천하대세 라운드

황건의 난·관도대전·적벽대전·이릉대전 중 하나가 게임 시작 시 선택되는 천하대세 시스템을 설계해줘. 각 대세는 상점 확률·몬스터·전역 버프 중 최대 두 요소만 바꾸고, 특정 세력만 일방적으로 유리하지 않게 해줘.

### 8. 상점 UX 고도화

현재 5칸 상점을 유지하면서 카드 구매 가능·대기석 부족·합성 임박·활성 인연 편입 가능 여부를 카드에 명확히 표시해줘. 기존 먹빛 스타일을 유지하고 색상만으로 상태를 구분하지 말아줘.

### 9. 튜토리얼

처음 접속한 사용자를 위한 7단계 인터랙티브 튜토리얼을 만들어줘. 조조 구매, 대기석 확인, 전장 배치, 위 시너지 활성화, 리롤, 상점 잠금, 전투 시작을 실제 UI에서 수행하게 하고 완료 상태는 로컬 저장해줘.

### 10. 모바일 관전 모드

모바일에서는 복잡한 편집 기능 대신 전투·조합·상점 상태를 보는 관전 모드를 먼저 제공해줘. 390×844에서 세로로 최적화하고, 전장 확대·시너지 접기·상점 가로 스와이프·전투 기록을 지원해줘.
